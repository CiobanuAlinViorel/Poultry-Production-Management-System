### Parent POM responsibilities

The parent POM does exactly three things and nothing else:

- Declares `<modules>` listing all four services and shared-kernel.
- Manages dependency versions via `<dependencyManagement>` (Spring Boot BOM, jjwt, MapStruct, Testcontainers, Flyway).
- Manages plugin versions via `<pluginManagement>`.

It has **no `<dependencies>` section** (only `<dependencyManagement>`). It has **no build configuration** that could bleed into services. It is not a Spring Boot app.

## 2. Shared Kernel — Full Contents

### 2.1 What belongs in the shared kernel

The shared kernel is code that is **identical** across all four services and has **no domain-specific logic**. It is infrastructure plumbing and cross-cutting concerns only.

| Category | Included | Rationale |
|---|---|---|
| User & Role entities | `User`, `UserRoleAssignment`, `Role` | Every service validates JWT and looks up roles |
| Employee entity | `Employee` | Person reference independent of system access |
| Audit log | `AuditLog` entity + AOP interceptor | Every service writes audit records |
| Alert & Notification | `Alert`, `Notification`, `AlertAcknowledgement` | Generated by all services, same structure |
| JWT utilities | `JwtTokenProvider`, `JwtAuthenticationFilter` | Each service validates tokens independently |
| Global exception types | `DomainException`, `EntityNotFoundException`, `ValidationException`, `BusinessRuleViolationException` | All services throw the same exception hierarchy |
| Error envelope | `ApiErrorResponse`, `FieldValidationError` | Consistent API error contract across all services |
| Pagination wrapper | `PageResponse<T>` | Consistent paginated list response shape |
| Audit AOP | `AuditInterceptor` (@Aspect) | Intercepts write operations across all services |
| Base entity | `BaseEntity` (abstract, with `createdAt`, `updatedAt`) | All JPA entities extend this |
| Enum: `ServiceModule` | `PARENT_FLOCK`, `HATCHERY`, `FARM`, `SLAUGHTERHOUSE` | Used in `AuditLog.serviceModule` and `Alert.sourceModule` |

### 2.2 What must NOT be in the shared kernel

These are common mistakes that couple services and must be avoided:

- **No domain entities** from any of the four bounded contexts. `ParentFlock`, `Lot`, `IncubationBatch` — none of these belong here.
- **No Spring Boot `@SpringBootApplication`**. The kernel is a plain JAR.
- **No `@ComponentScan`** or Spring auto-configuration. Each service scans its own packages.
- **No Flyway migrations**. The kernel has no schema. Each service owns its own migrations entirely.
- **No cross-service business logic**. If a rule involves knowing something about a flock and a hatchery at the same time, it belongs in neither service alone and should be a future orchestration layer.
- **No `application.yml`**. Configuration is per-service.
- **No controllers or `@RestController`**. The kernel has no HTTP endpoints.

### 2.4 Entity and class inventory

#### `BaseEntity`
```
@MappedSuperclass
abstract class BaseEntity {
    @Id UUID id                        ← generated UUID, never exposed directly in URLs
    @CreationTimestamp Instant createdAt
    @UpdateTimestamp  Instant updatedAt
}
```
All domain entities across all services extend `BaseEntity`. This gives every entity a consistent primary key type and automatic timestamps without repeating the fields.

#### `User`
```
class User extends BaseEntity {
    String username                    ← unique
    String passwordHash                ← bcrypt cost ≥ 12
    String email                       ← unique
    boolean isActive
    boolean isLocked
    int failedLoginAttempts            ← locked after 5
    Instant passwordExpiresAt
    Instant lastLoginAt
}
```

#### `Employee`
```
class Employee extends BaseEntity {
    String firstName
    String lastName
    String nationalId                  ← unique
    String phone
    String jobTitle
    LocalDate hireDate
    UUID userId                        ← FK to User, nullable (person may not have system access)
}
```

#### `Role`
```
class Role extends BaseEntity {
    String roleName                    ← e.g. "FLOCK_SUPERVISOR"
    String description
    ServiceModule module               ← which service owns this role
}
```

#### `UserRoleAssignment`
```
class UserRoleAssignment extends BaseEntity {
    UUID userId
    UUID roleId
    RoleScope scopeEntityType          ← FLOCK_HOUSE / FARM_SITE / HATCHERY / SLAUGHTERHOUSE
    UUID scopeEntityId                 ← the specific entity this role applies to
    UUID assignedBy
    Instant assignedAt
    Instant expiresAt                  ← nullable — permanent if null
}
```

#### `AuditLog`
```
class AuditLog extends BaseEntity {
    UUID userId
    ServiceModule serviceModule
    String action                      ← CREATE / UPDATE / DELETE
    String entityType                  ← simple class name
    UUID entityId
    String changesJson                 ← before/after diff as JSON
    Instant performedAt
    String ipAddress
}
```
Note: `AuditLog` has **no update or delete** repository methods exposed. The repository only provides `save()` and `findBy*()`. This is enforced at the repository interface level.

#### `Alert`
```
class Alert extends BaseEntity {
    AlertSeverity severity             ← INFO / WARNING / CRITICAL
    ServiceModule sourceModule
    String alertCode                   ← e.g. "LAYING_RATE_BELOW_THRESHOLD"
    String relatedEntityType
    UUID relatedEntityId
    String message
    Instant generatedAt
    AlertStatus status                 ← OPEN / ACKNOWLEDGED / DISMISSED
}
```

#### `Notification`
```
class Notification extends BaseEntity {
    UUID userId
    UUID alertId                       ← nullable — some notifications aren't from alerts
    String subject
    String body
    boolean isRead
    Instant readAt

}
```

```
class AlertAcknowledgement extends BaseEntity {
    UUID alertId
    UUID acknowledgedBy
    Instant acknowledgedAt

}
```

### 2.5 Key implementation details

**JWT validation.** Each service loads `JwtAuthenticationFilter` as a `@Bean` in its own `SecurityConfig`. The filter extracts the Bearer token, delegates to `JwtTokenProvider.validateToken()`, and populates `SecurityContextHolder`. No auth server. No shared session. The shared secret is configured per service via `ppms.jwt.secret` in `application.yml`.

**AOP audit interceptor.** Methods annotated with `@Audited` in any service trigger `AuditInterceptor`, which captures the actor from `SecurityContextHolder`, serialises the before/after state of the return value, and writes to `AuditLog`. The service name comes from `ppms.service.module` in `application.yml`. Annotate service methods, not controllers.

**Exception hierarchy.** Controllers never throw checked exceptions. The service layer throws subtypes of `DomainException`. Each service has its own `@ControllerAdvice` that catches these and maps them to `ApiErrorResponse` with the right HTTP status. The mapping is:

```
EntityNotFoundException           → 404
BusinessRuleViolationException    → 409
WithdrawalPeriodActiveException   → 409
ValidationException               → 400
DomainException (generic)         → 500
```

### 4.1 Schema ownership

```
PostgreSQL instance (single, for local dev):
├── schema: shared           ← users, roles, audit_log, alert, notification
├── schema: parent_flock     ← all entities in this service
├── schema: hatchery         ← (other service)
```

The `parent_flock` schema contains **only** the tables owned by this service. There are no foreign key constraints from `parent_flock` tables to tables in other schemas. Cross-context references are plain UUID columns with no DB-level constraint.

The `shared` schema is read by all four services (user lookup, role lookup). Each service connects to the same PostgreSQL instance but is configured with a dedicated database user that has read/write on its own schema and read-only on `shared`.

## 5. Business Rules — Implementation Instructions

These are invariants. Every rule is checked in the **service layer** before any persistence call. The controller does only format/type validation (`@Valid`). The database constraint is the last line of defence for uniqueness only.

| Rule | Where to implement | Exception to throw |
|---|---|---|
| Duplicate daily sheet (same house + date) | `DailyOperationsService.createDailySheet` checks `existsByHouseIdAndOperationDate` before `save` | `BusinessRuleViolationException("Daily sheet already exists for house {code} on {date}")` |
| Egg collection only in PRODUCTION phase | `DailyOperationsService.addEggCollection` checks `sheet.phaseType == PRODUCTION` | `BusinessRuleViolationException` |
| `EggTransferOrder` blocked by active withdrawal | `EggTransferOrderService.createOrder` calls `HealthInterventionRepository.findByFlockIdAndWithdrawalEndDateGreaterThanEqual(flockId, scheduledDispatchDate)` — if result non-empty: block | `WithdrawalPeriodActiveException` — this specific exception type must be used so the controller advice maps it to 409 with a distinct error code the frontend can act on |
| `EggTransferOrder` requires PASSED quality inspection | `EggTransferOrderService.createOrder` loads the inspection and checks `outcome == PASSED` | `BusinessRuleViolationException` |
| `EggTransferOrder` quantity cannot exceed Grade 1 stock | `EggTransferOrderService.createOrder` loads `EggStockLedger` and checks `plannedQuantity ≤ grade1Available` | `BusinessRuleViolationException` |
| `EggSaleOrder` quantity cannot exceed Grade 2 stock | `EggSaleOrderService.createOrder` sums `EggSaleOrderLine.quantity` and checks against `grade2Available` | `BusinessRuleViolationException` |
| House type must match flock phase | `FlockService.registerFlock` checks house.houseType == REARING; `FlockService.recordPhaseTransfer` checks destination house.houseType == PRODUCTION | `BusinessRuleViolationException` |
| Cannot assign flock to occupied/non-empty house | `FlockService.registerFlock` and `FlockService.recordPhaseTransfer`: destination house.status must be EMPTY | `BusinessRuleViolationException` |
| Only FLOCK_VET creates health interventions | `@PreAuthorize("hasAuthority('FLOCK_VET')")` on `HealthService.createIntervention`, `createScheduleEntry`, `recordHealthEvent`, `recordBiosecurityInspection` | Spring Security throws AccessDeniedException → mapped to 403 |
| Stock FIFO consumption | `InventoryService` and `HealthService`: when consuming from stock, always call `FlockStockBatchRepository.findByConsumableTypeIdAndFarmSiteIdAndQuantityRemainingGreaterThanOrderByExpiryDateAsc` and consume earliest-expiry batch first, cascading to next batch if quantity insufficient | `BusinessRuleViolationException("Insufficient stock of {consumableName}")` |
| Stock deduction cannot go negative | `EggStockService.debitStock` checks balance before writing | `BusinessRuleViolationException` |
| Culling counts cannot exceed live bird counts | `FlockService.recordCulling`: hensCulled ≤ currentHenCount AND cocksCulled ≤ currentCockCount | `BusinessRuleViolationException` |
| Transfer quantities cannot exceed available birds | `FlockService.recordPhaseTransfer`: sum of all destination.transferredHenCount ≤ currentHenCount, same for cock | `BusinessRuleViolationException` |
| FAILED stock batch cannot be consumed | `InventoryService` FIFO query filters out batches with qualityStatus FAIL or QUARANTINE | `BusinessRuleViolationException("Batch {batchNumber} is quarantined and cannot be used")` |
| Daily sheet cannot be edited after SUBMITTED | `DailyOperationsService` checks `sheet.status == DRAFT` before any update | `BusinessRuleViolationException` |
| Withdrawal period NFR: must be a domain invariant, not only API validation | The withdrawal check in `EggTransferOrderService` must call a dedicated `WithdrawalPeriodChecker` domain service, not inline SQL. This ensures the check can be unit-tested in isolation without a database. | — |

## 6. Cross-Service Integration Contract

### How the Hatchery service knows about an EggTransferOrder

The Hatchery service does **not** have a JPA entity mapping to the Parent Flock schema. It reads transfer orders via REST.

```
Parent Flock Service → Hatchery Service
────────────────────────────────────────
Trigger:   EggTransferOrderService.dispatchOrder()
Action:    HatcheryIntegrationClient.notifyIncomingTransfer(order)
Endpoint:  POST hatchery-service/api/v1/egg-receptions/incoming-notification
Payload:   {
               transferOrderId: UUID,
               transferCode: String,
               sourceFlockId: UUID,
               flockCode: String,
               farmSiteId: UUID,
               plannedQuantity: int,
               scheduledDispatchDate: LocalDate,
               qualityInspectionSummary: { crackRatePercent, outcome }
           }
Auth:      Bearer JWT with claim "service": "PARENT_FLOCK"

Hatchery Service → Parent Flock Service
────────────────────────────────────────
Trigger:   Hatchery operator confirms receipt
Action:    PUT parent-flock-service/api/v1/integration/egg-transfer-orders/{id}/received
Payload:   { receivedQuantity: int, receivedAt: Instant, discrepancyNotes: String }
Auth:      Bearer JWT with claim "service": "HATCHERY"
Handler:   IntegrationController → EggTransferOrderService.receiveConfirmation()
```

The `status` field on `EggTransferOrder` is the integration contract. The Hatchery service may also poll `GET /api/v1/egg-transfer-orders?status=DISPATCHED` to discover incoming eggs without relying on the push notification (resilience fallback).

## 8. Testing Strategy

### Unit tests (no Spring context, no database)

- One test class per service class.
- Use Mockito to mock all repository dependencies.
- Test every business rule in isolation — particularly the withdrawal period block, the stock FIFO logic, the phase-transition validations, and the egg stock balance checks.
- Test naming convention: `methodName_condition_expectedBehaviour`.

```
FlockServiceTest
    registerFlock_houseNotEmpty_throwsBusinessRuleViolationException
    registerFlock_houseIsRearingType_createsFlockAndSetsHouseOccupied
    recordPhaseTransfer_partialTransfer_updatesOnlyTransferredCounts
    recordCulling_countExceedsLiveBirds_throwsBusinessRuleViolationException

EggTransferOrderServiceTest
    createOrder_activeWithdrawalPeriod_throwsWithdrawalPeriodActiveException
    createOrder_failedQualityInspection_throwsBusinessRuleViolationException
    createOrder_quantityExceedsStock_throwsBusinessRuleViolationException
    dispatchOrder_debitsLedgerByActualQuantity

EggStockServiceTest
    debitStock_balanceWouldGoNegative_throwsBusinessRuleViolationException
    creditStock_incrementsBothLedgerAndLedgerEntry

DailyOperationsServiceTest
    createDailySheet_duplicateHouseAndDate_throwsBusinessRuleViolationException
    addEggCollection_rearingPhaseSheet_throwsBusinessRuleViolationException
    submitSheet_creditsEggStockLedger
```

Target: ≥ 70% line coverage on all service classes (enforced by JaCoCo in the Maven build).

### Integration tests (real PostgreSQL via Testcontainers)

- Use `@SpringBootTest` with a Testcontainers `PostgreSQLContainer`.
- One integration test class per major flow, not per endpoint.
- Test the full vertical slice: HTTP request → controller → service → repository → database → response.
- Use `@Sql` to seed test data per test method or test class.

```
FlockLifecycleIntegrationTest
    givenRearingFlock_whenTransferredToProduction_thenHouseStatusChangesAndPhaseUpdates
    givenProductionFlock_whenFullyCulled_thenPhaseSetToCulledAndHouseSetToCleaning

EggTransferOrderIntegrationTest
    givenPassedInspectionNoWithdrawal_whenOrderCreated_thenStatusPlanned
    givenActiveWithdrawal_whenOrderCreated_thenReturn409WithdrawalPeriodActive
    givenDispatchedOrder_whenHatcheryCallsBack_thenStatusSetToReceived

DailyOperationsIntegrationTest
    givenProductionFlock_whenDailySheetSubmitted_thenEggStockLedgerCredited
    givenSubmittedSheet_whenDuplicateAttempted_thenReturn409

InventoryIntegrationTest
    givenTwoBatchesDifferentExpiry_whenConsumed_thenEarliestExpiryDeductedFirst
```

### Test data & builder pattern

Create a `TestDataBuilder` class (test scope only) with static factory methods for each entity. This avoids repeating constructor calls across tests and makes test intent readable:

```java
TestDataBuilder.aFlock()
    .withFarmSite(savedFarmSite)
    .withRearingHouse(savedHouse)
    .withPhase(FlockPhaseStatus.PRODUCTION)
    .build();

TestDataBuilder.anEggTransferOrder()
    .forFlock(savedFlock)
    .withStatus(TransferOrderStatus.APPROVED)
    .build();
```
